# Stage 7D：有效匹配、轨迹与2D–3D支持的最小诊断协议

## 本轮边界与冻结

用户批准先冻结方案与停止条件。本轮只检查既有缓存结构、固定清单和本协议，不开发算法、不执行诊断或新实验、不下载数据、不提交或推送。独立分支为`codex/stage7d-support-diagnostic-protocol`，代码基线`0715e4e1acc8d1326faaef4b8571c8313ebf320e`；不合并main。**下列诊断执行均待用户另行批准，本文件不是已完成诊断的报告。**

[冻结清单](../configs/experiments/stage7d_support_diagnostic_v1.json)锁定Stage7C输入索引、既有评价、审计、算法源码，以及960份record和960份map的集合摘要。摘要按相对路径排序，逐文件拼接`路径 + NUL + SHA256 + LF`后再取SHA256。后续执行先校验清单、集合数量/摘要及旧`input_hashes.json`中的相关特征/匹配哈希；缺少、额外或改变的文件不静默接受。原图仅可用作已存在的尺寸/预处理出处，本诊断不读取原图像素、不读取描述子或模型权重。

本阶段目标是定位证据支持的失效环节，判断是否存在值得另立假设的工程瓶颈；不证明修复收益，不把AP3P重新判为通过，不改变两排序或旧默认。Stage7C的`NO_GO_CONFIRMATION`及全部历史负结果继续有效。

## 固定范围与比较单位

- 仅用`outputs/stage7c_data_v1/`与`outputs/stage7c_confirmation_v1/`。DTU scan12/13/15、TUM desk2/room/teddy；normal5/reduced3/spaced3/blur5四条件；种子42–46、B/C、内点/质量、EPnP/AP3P，共960份既有记录。缺失/错误/无种子全部保留，不增加Stage7B、替换帧或扩充场景。
- C为主诊断，B单列为前端对照；两排序与两PnP方法分开，不能混合挑优。相同输入/前端的原始匹配图只计算一次，共24×2=48组，重复使用不能当作独立样本。
- 全960记录先做计数与阶段状态汇总；支持归因以实际PnP尝试为单位，另报告每输入条件、场景、种子的分布。无种子属于独立失败分支，不伪造PnP尝试或把不适用写成零支持。
- 地图/相机正确性只关联既有`evaluation.json`及已发布配对CSV，用于分层描述。诊断特征先独立生成并固定哈希，再关联旧标签；不读取GT相机、计算新GT误差或用标签挑参数。现有留出集已经用于验收，不再称独立确认集。

## 四层诊断及指标

| 层次 | 固定操作与输出 | 能证明和不能证明的内容 |
|---|---|---|
| 1. 原始匹配与身份 | 读现有NPZ关键点和匹配索引；核查有界索引、有限坐标、canonical方向、重复边、同图关键点一对多。逐对报告匹配数、唯一端点数、8×6网格占用率 | B/C使用共享特征身份，仍须核查；数量与空间覆盖不代表匹配正确 |
| 2. 轨迹拓扑 | 观测节点为`(image key, keypoint index)`，边为缓存匹配；固定并查集/连通分量统计。报告2视图/≥3视图分量数、涉及观测数、同一分量同图多关键点冲突率；三图闭环报告闭合、缺边、冲突及可判定分母 | 只是原始匹配图的拓扑一致性，不是几何验证轨迹。冲突分量不强行拆分、合并或选择成员；缺边不是已知错配 |
| 3. 种子与2D–3D支持漏斗 | 从已有signals/selection/steps读取匹配→E内点→种子保留点、种子失败原因、候选链接/唯一链接/内点/拒绝原因。可恢复时分解支持重复与身份冲突；对照既有`collect_links`语义 | 定位“支持在哪里消失”；不能将候选数减唯一数全算冲突，也不能把被拒绝的候选当正确点 |
| 4. 具备支持后的失败 | 单列唯一链接≥原12点门的RANSAC失败、正深度/重投影门拒绝与成功；其余为不足支持。关联已有正确性标签，保留原失败分母 | 不重估E/H/PnP、不三角化、不BA，不改12点/2px等门。缺少RANSAC掩码、拒绝细分或中间状态时只报告已有原因，不猜测内点质量或物理根因 |

闭环定义固定为三个不同图像中，节点a经两条边到c时，检查第三条a–c边是否存在；多重对应单列冲突，不选一个使其闭合。逐无序图像三元组报告唯一节点三元组，重复路径去重；没有两边可比较时为不适用，不给“100%一致”。不按像素接近自动合并不同关键点，也不凭图连通新增3D点或注册。

### 精确支持归因的可评估范围

现有runner未保存`debug`中的逐步链接数组、完整种子接受掩码和每一步观测表，只保存最终`map.npz`的xyz/observations、record计数与BA前位姿。**不允许为补日志重跑原SfM。**

1. 对成功种子，用seed step的`kept_points`和最终观测中的point ID前缀恢复原种子观测身份。先验证ID连续、每个种子点在两张种子图恰有一条观测，且相关源码保证BA不改变观测身份。失败即标`seed_identity_unavailable`，不用BA后的xyz替代原种子几何。
2. 只对目标视图处理前尚无任何后续成功注册的PnP尝试做精确重建。这时原活动观测仅来自两种子图，且点数应仍等于种子点数。按原有方向拼接匹配到种子点的候选，复算候选总数、去重候选对数和双向无歧义链接数，要求与record的`candidate_links/unique_links/points_before`逐项一致。集合、去重与计数不调用几何求解器。
3. 候选总数减去唯一候选对数记为重复支持；在去重集合上分别统计一key对应多point、一point对应多key及两者交集。用与`collect_links`等价的双向唯一条件统计保留数，验证集合守恒。不能重复计入两种冲突，不能把两张种子图支持同一对应当成两个可用3D点。
4. 已有成功注册之后的尝试，仅保留原计数、时序与拒绝原因，标记`intermediate_state_unavailable`，不从最终观测倒推当时状态。无种子不能恢复真实锚点。替代种子的signals仅作既有摘要，不重构其未保存的匹配/地图。

在上述可评估尝试上，额外报告“无同图冲突、恰连一个现有种子landmark的原始分量”中，目标视图经**已有图边**可达的唯一锚点数，以及其中缺少直接链接的数量。该数量只是拓扑潜在支持，不代表有效2D–3D对应、可恢复相机或改进收益；冲突分量/多landmark分量单列排除。禁止据此传播匹配、合并landmark或模拟修改后的PnP结果。

## 固定解释规则、对照和不可评估

| 既有证据形态 | 允许的诊断结论 |
|---|---|
| 无成功种子 | 仅按已有signals/attempts报告种子阶段原因；没有证据说明新轨迹方法可救回 |
| 精确恢复后，去重候选对<12 | 当前种子与直接匹配下支持数量不足；不是全场景或所有种子不可恢复的证明 |
| 去重候选对≥12、双向唯一链接<12 | 身份冲突使原注册门不可达；不能靠放松冲突门宣称修复 |
| 直接唯一支持<12、无冲突分量的潜在锚点≥12 | 原始拓扑存在值得核查的间接支持，几何有效性未知；不是“已证明漏掉正确轨迹” |
| 唯一链接≥12仍拒绝 | 数量门已过，按缓存拒绝原因定位；缺少掩码时不能进一步断言几何分布、错配或求解器根因 |
| 路径/关键点/身份/计数无法一致复原 | 保留`unavailable`或`inconsistent`及精确原因，停止该条归因；不补算、不用默认值填充 |

全部C/legacy与C/AP3P对应记录保留，先核对共享种子；两排序按各自真实种子分析，不用GT替换。B/C按相同视图和关键点身份比较，但不把不同种子引起的差异全归给匹配前端。报告同种子/不同种子分层及其分母；无法公平配对者单列。

预固定代表案例：scan12_spaced3（局部准确恢复）、scan13_blur5（新增错误/回退）、三个TUM序列的全部四条件。其余DTU条件同样进入完整汇总，不只看失败或有利案例。错误接受标签不是拓扑正确性的oracle；本轮不构建“最佳方法”或“新增对应真实正确数”的oracle。

## 预算、停止与继续条件

未来若获执行授权：仅CPU、单进程、BLAS/OMP线程各1、GPU0（不超过12GB），网络0；总墙钟600秒、RSS8GiB、新产物64MiB。流式逐图/记录处理，不枚举指数路径；预算到达即停止，已完成/未执行/不适用/不可评估/失败分开。不得缩减输入、放宽阈值或覆盖旧产物以凑完成。

- **技术停止**：冻结哈希、缓存完整性或身份不一致时停止对应来源的归因；保留精确路径/原因，其他独立可读记录可继续只读统计。若关键缺失使主要问题不可回答，阶段结论为证据不足，不擅自新增几何回放或日志采集。
- **诊断结束**：仅完成一次固定范围审计，输出一份简洁结论及必要CSV，不调参、不训练、不改匹配/轨迹/种子/PnP/BA。未注册、无种子和不可评估始终留在总分母；条件比例、场景比例、随机种子重复分别报告，不做显著性或独立样本量夸大。
- **值得另提改进假设的门**：同一具体支持瓶颈在至少2/3个TUM序列、各至少2/4条件出现；每个所计条件须五个种子的C/legacy记录均可精确评估且支持该归因，两排序分别检验。还须由缓存指出可操作环节（如可计数的冲突损失或非冲突间接锚点缺口），而非仅“匹配少”。这只是保守的研究优先级门，不是算法性能验收门，不能证明新增支持正确。
- **停止该路线**：达不到上述门，或主要只有单物体/单条件、不可恢复中间状态、潜在图连通而无可操作证据，则不启动轨迹修复开发。若支持已足但几何仍拒绝，只定位为另一类问题，不自动改成求解器搜索。满足优先级门也只提出一个最小假设和另行验证计划，等待用户批准，不进入开发或试验。

未来执行拟产物限于新建且拒绝覆盖的`outputs/stage7d_support_diagnostic_v1/`，包括来源哈希、48图拓扑摘要、960记录状态与尝试级支持表、不可评估/不一致清单、资源统计；大表和原始日志默认不进Git。只有执行获批后才实现只读诊断入口及必要的身份/守恒测试。本轮仅新增本协议与冻结JSON，不产生诊断结论、脚本或测试。

累计贡献仍是受控重建工程与负结果证据链；本协议进一步约束因果归因和缓存证据边界，尚无新的性能收益或原创算法贡献。
