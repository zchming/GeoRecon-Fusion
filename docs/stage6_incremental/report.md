## 协议与实现

K 是明确许可的输入；1600×1200原图沿用800×600双线性预处理，K_processed=A K_original，像素中心平移为−0.25。每图独立K，畸变已由DTU校正。位姿、尺度和参考点不进入重建进程；输入字段白名单拒绝R/t，运行审计钩子阻断参考文件读取，访问清单随运行归档。此防误用护栏不等同于操作系统级安全沙箱。

每图只提取一次SIFT，4096为目标特征数；L2双向比率0.75和互检。种子复用已冻结的E估计与DLT。匹配已注册视图的关键点，获得新图像关键点→已有三维点对应；身份冲突双向剔除，同一关键点或同一地标只保留唯一对应。PnP最少12对、1000次RANSAC、概率0.999，随机种子42。完整K逆变换归一化后以单位K调用EPnP，避免忽略K中的skew；归一化阈值2px/平均焦距是各向异性焦距下的近似，最终必须通过完整K的2px重投影和正深度检查。未做额外位姿细化。

注册后，以估计相机的相对位姿执行DLT，只为两端尚未归属的关键点创建新地标，要求正深度、视差≥0.5°、两端误差≤2px。从旧相机坐标转换回种子世界坐标；首相机I/0，种子基线长1。已有相机和点保持不变。失败图像不写入相机，不破坏已建立的模型；允许partial结果。未做轨迹合并、回环、重复点融合或全局优化。

OpenCV的PnP返回world-to-camera位姿；算法与约定参考[官方说明](https://docs.opencv.org/4.x/d5/d1f/calib3d_solvePnP.html)。这是经典算法教学实现，不是新的PnP或SfM算法。

## 验证、成本和失败保存

126项不同测试分两个环境交叉覆盖：OpenCV环境运行126项、跳过1项原生COLMAP；COLMAP环境运行126项、跳过26项依赖OpenCV的测试，均通过。新增6项覆盖带skew已知K的PnP坐标约定、噪声/离群点、对应不足、共线退化、轨迹身份冲突，以及任意已注册相机下的三角化世界坐标转换。

独立检查脚本对5组完整流程精确重放，核对全部debug数组、注册步骤、点坐标与轨迹；检查每个(view,keypoint)和(view,landmark)唯一、全部已接受观测正深度/重投影门限，以及已有种子位姿和点逐元素不变。保存实际退出码，普通成功为0，部分/初始化失败为1；没有把可预期失败伪装成进程错误。

5组进程主体总计1.363秒，控制器含启动与GPU采样总计2.532秒；峰值进程RSS 0.217 GiB。主体时间包括加载、特征、几何及主要产物压缩，末尾JSON写入不在主体计时中；这些是单次小样本实测，不是稳定速度排名。

使用CPU OpenCV/NumPy、8线程，OpenCL关闭，无CUDA模型或显存分配（任务新增0字节）。控制器实测整卡503–507MiB/12282MiB，包含桌面，不等于任务显存；计算进程列表为空，WSL进程枚举有局限。预算为12GB以内；本轮无需GPU模型推理，也未调用付费资源。

本地 outputs/stage6_incremental_v1 保留完整NPZ：所有候选匹配、PnP候选位姿/内点/深度/误差、新点三角化的接受与拒绝掩码，以及地标来源、观测表和最终点。Git仅保存代码、配置、轻量JSON、原始stdout/stderr与测试报告；原始图像、权重和NPZ不入库。

## 复现

在已安装teaching extra和NumPy/Pillow的环境，设置PYTHONPATH=src：

```bash
python -m georecon.teaching.incremental_run --input data/stage6_incremental/dtu_scan1_normal5/input.json --config configs/teaching/stage6_incremental.json --output outputs/my_new_incremental_attempt
python scripts/check_stage6_incremental.py
python -m unittest discover -s tests -v
```

输入准备脚本仅在不存在锁定输入时运行；运行器拒绝覆盖任何既有输出。复现新运行必须使用新的输出目录，不能覆盖此次记录。原始DTU数据不包含在Git中。
