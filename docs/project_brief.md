# 一、项目定位

项目名称：

**GeoRecon-Fusion：基于视觉几何基础模型与经典几何融合的可靠性驱动多视图三维重建系统**

英文名称：

**GeoRecon-Fusion: Geometry-Reliability-Aware Hybrid Multi-View 3D Reconstruction**

项目用于三维视觉、视觉几何、多视图重建相关实习求职。最终成果必须能够支持代码审查、实验复现和面试追问。

项目的核心研究问题是：

> 经典 SfM/MVS 与视觉几何基础模型在不同输入条件下具有哪些失败模式？能否通过无需测试集真值的几何可靠性判断，选择或融合它们的估计，在重建精度、完整度、成功率和计算成本之间获得更好的结果？

“融合能够提升性能”是待验证的假设，不能提前作为结论。只要实验严谨，发现融合无效或仅在特定条件下有效，也属于有效成果。

# 三、技术路线

系统分为四部分。

## 1. 教学版经典几何模块

实现一个可解释、可调试的小型 SfM，用于学习和展示几何基础：

- 特征提取与匹配；
- 匹配过滤与 RANSAC；
- 已知或估计内参条件下的 Essential Matrix；
- 相对位姿恢复；
- 三角化与正深度检查；
- PnP 与增量注册；
- 重投影误差计算；
- 小规模 Bundle Adjustment。

优先使用 OpenCV 和成熟数值优化库，不必从零重写求解器。

明确标记实现范围、内参假设和退化情况。该模块主要用于几何理解和面试展示，不要求达到 COLMAP 的工程完整度，也不默认承担正式大规模 Benchmark。

## 2. 经典方法与基础模型 Baseline

正式实验优先接入：

- **COLMAP SfM**：评估相机位姿、注册情况和稀疏结构；
- **COLMAP SfM + MVS**：在环境支持时评估稠密重建；
- **VGGT 原始推理**：保留明确的默认配置和后处理；
- **VGGT + 官方支持的几何优化/BA**：核实当前官方实现后接入。

必须先检查 VGGT 和 COLMAP 的官方文档、代码、许可证及硬件要求，记录仓库地址、版本或 commit、权重来源和运行参数。不要凭记忆假定接口存在。

如果 VGGT 官方流程已经包含跟踪、COLMAP 导出或 BA，这些功能属于 Baseline，不能包装成本项目的原创贡献。

额外模型暂不加入，除非我明确要求或现有 Baseline 无法支撑实验问题。

## 3. Geometry Reliability Analysis

构建推理阶段不依赖真值的可靠性分析模块，候选信号包括：

- 基于独立观测匹配的重投影残差；
- 多视图深度或三维点一致性；
- 正深度比例、三角化夹角和轨迹长度；
- 匹配内点比例与视图连接情况；
- 模型输出的置信度；
- 局部覆盖情况。

注意：

- 区分像素、匹配、轨迹、视图和场景级可靠性；
- 优先实现少量可解释信号，不要一开始堆叠全部信号；
- 不能把模型由自身深度和相机生成的点再投影回自身图像，所得低残差直接当成独立正确性证据；
- 模型置信度不等于已校准的正确概率；
- 跨方法分数必须考虑量纲和校准；
- 没有匹配、无法注册或证据不足时，保留“未知/不可评估”状态，不能直接赋予高可靠性。

使用开发集分析可靠性与真实误差的关系；真值只用于评估和开发集校准，不得进入测试时的可靠性计算。

## 4. Reliability-Aware Selection / Fusion

按从简单到复杂的顺序验证：

1. **场景级选择**：根据可靠性，在不同重建结果之间选择或回退；
2. **过滤与优化**：利用可靠性过滤点、轨迹或几何约束；
3. **加权融合或联合优化**：只有前两步结果支持继续投入时才实现。

不要默认直接平均两套相机或点云。

必须处理：

- 相机内外参定义；
- world-to-camera 与 camera-to-world；
- 图像缩放、裁剪和内参同步；
- 坐标轴、深度定义和单位；
- 单目重建的尺度不确定性；
- 必要的 SE(3)/Sim(3) 对齐；
- COLMAP 部分注册或完全失败时的回退。

推理融合所需的对齐必须来自可用的图像对应、相机或结构信息，不能使用测试集真值。用于计算评价指标的真值对齐，应与推理流程分开实现并清楚记录。

具体融合算法应由 Baseline 失败分析决定，不要提前承诺未经验证的复杂方法。

- 能明确复现划分、采样和评价过程。

实验条件优先包括：

- 正常输入；
- 图像数量减少；
- 视图重叠降低；
- 模糊或曝光扰动；
- 有数据支持的低纹理等困难场景。

必须说明条件如何构造。减少图像数量不自动等价于降低重叠。合成扰动应记录生成参数，与真实困难场景分别报告。

固定并保存：

- 场景清单；
- 开发集和测试集划分；
- 输入图像清单及顺序；
- 图像预处理；
- 随机种子；
- 扰动参数；
- 各方法预算和运行配置。

同一场景的不同扰动版本不得跨开发集和测试集造成泄漏。方法参数只能用开发集选择，不能根据测试集表现反复调整。

# 五、评价指标与公平比较

按任务分别报告指标，避免把不同输出直接混为一谈。

## 相机与 SfM

根据数据集协议选择：

- 注册图像比例；
- 场景成功率；
- 相对旋转、平移方向误差及对应 AUC；
- 对齐后的相机中心误差或 ATE。

说明平移方向与位置误差的区别、对齐方式、误差单位和计算对象。

对部分注册结果，同时报告覆盖率及已注册子集上的误差。不得只挑成功图像计算误差后声称整体表现更好。

## 稠密几何

有合适真值时报告：

- Accuracy；
- Completeness；
- 指定阈值下的 Precision、Recall 和 F-score；
- 适用时的 Chamfer Distance。

记录距离定义、阈值、单位、评价区域、点采样方式和对齐协议。优先遵循数据集官方评价实现。

## 计算成本

报告：

- 总耗时及主要阶段耗时；
- 峰值显存；
- 使用的 GPU/CPU、软件版本；
- 输入数量和分辨率。

区分模型加载时间与推理时间。混合方法必须计入它实际运行的所有分支、可靠性分析和融合成本。

## 汇总规则

- 保存逐场景结果，再计算均值、中位数和失败统计；
- 预先定义成功、失败、超时和显存不足的判定；
- 所有失败都进入结果表；
- 比较时保持输入图像一致，并披露各方法必要的分辨率或相机假设差异；
- 精度、覆盖率和耗时应一起解读，避免单指标排名。
